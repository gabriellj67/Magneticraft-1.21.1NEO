# Magneticraft 1.0.0 视觉保真与发布验收

## 结论

1.0.0 将 Nova 1.12 的 MCX/glTF 资产转换为 Forge 1.20.1 可烘焙的 OBJ/MTL，
恢复了关键机器的历史主体、方向和活动部件。动态表现只消费服务端权威或世界权威
状态，并具有固定帧数、节点数、连接数、顶点数或渲染距离上限。运行时不包含旧
模型加载器。

最终审计同时关闭了注册层的通用占位 ID。57 个方块实体、37 个菜单、10 个配方
类型和 10 个配方序列化器均按所属内容注册；运行时禁止重新出现
`single_block_machine`、`advanced_multiblock`、`programmable`、
`advanced_processing` 和 `fluid_fuel` 等通用注册 ID。迁移矩阵仍是行为归属权威，
现有实现只有通过矩阵契约与测试后才被保留。

## 视觉对齐矩阵

| 验收面 | 1.12 权威表现 | 1.0.0 实现 | 验收边界 |
|---|---|---|---|
| 机器方向 | 方块状态决定主体朝向 | 静态模型 blockstate 与 BER 共用机器朝向变换；电线杆支持 8 个 45°方向 | 不由客户端猜测服务端状态 |
| 活动部件 | glTF/MCX 命名部件动画 | 电动机、机械臂、粉碎机、筛选机、液压机、蒸汽机各使用 8 帧离线烘焙部件 | 每实例每帧只选择一个模型；停止时冻结第 0 帧 |
| 液面 | 储罐内容和数量决定液面 | 使用同步 FluidStack 与容量计算有上限表面；不复制隐藏库存 | 最多按机器声明的 5 个储罐渲染 |
| 传送带物品 | 物品沿皮带移动并在堵塞时停留 | BER 渲染实体外的同步 parcel；运输仍由服务端恰好一次结算 | 每皮带最多 16 个 parcel；无坡道/垂直表现 |
| 长距离导线 | 连接器、电线杆和多股铜线 | 历史静态端点/杆塔模型 + 自有分段导线 | 客户端快照最多 64 连接，每线最多 32 段，不加载区块 |
| Tesla 塔 | 三格塔体与工作状态 | 完整历史塔体只在底部烘焙，成员块为空模型，避免重复几何 | 服务端决定连接和能量，客户端只表现 |
| 风力涡轮机 | 五格尺度转子按风况旋转 | 历史轮毂与独立转子，使用同步转速绕原枢轴旋转 | 96 格 BER 视距；无运行时网格生成 |
| 电脑 | 机身、屏幕和运行状态 | 历史机身 + 独立屏幕；仅同步运行状态时全亮 | 不显示程序文本、软盘内容或不可见库存 |
| 采矿机器人 | 机身、双螺旋桨和五段钻头 | 历史机身、螺旋桨和钻头分别烘焙并按同步状态变换 | 移动、采掘和库存均由服务端验证 |

## 静态多方块决策

完整历史多方块外壳均被离线转换并注册到模型烘焙器，作为可执行的视觉比较基线。
世界内仍保留真实成员方块来表达碰撞、端口、破坏、掉落和结构归属；不在控制器
上重复覆盖一层同尺寸完整外壳，以免 Z-fighting、隐藏错误成员或让控制器成为唯一
视觉所有者。粉碎机、筛选机、液压机、蒸汽机、轮机、太阳能和工业燃烧室的历史
动态组件由控制器 BER 精确叠加。旧版泵井、油加热器和炼油厂渲染器本身是静态
模型，因此 1.0.0 不虚构机械动作。

## 资产与预算契约

- 清单固定 59 个逻辑资产与 8 个明确排除源；
- 6 组关键动画固定为 8 帧；
- 17 个完整历史外壳强制注册烘焙，用于发现丢失模型、材质和纹理；
- 蒸汽轮机固定复用 12 片历史叶片；
- 客户端资源中禁止 `.mcx`、`.gltf`、`.glb` 和外部 `.bin`；
- 转换器验证 890 个上游资源组成的固定资产树摘要；
- `--check` 逐字节验证全部 372 个生成文件。

4. 客户端日志无 Magneticraft 模型、MTL、纹理、方块状态加载错误；
5. 专服日志无客户端类加载、缺失映射、重复注册和网络线程错误；
6. 二进制与 sources JAR 含许可证和来源声明，不含 `.references`、Trellis、
   运行目录、旧模型格式或可选模组实现类。
