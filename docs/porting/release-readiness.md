# Magneticraft Forge 1.20.1 迁移可行性与首发验收报告

> 评估日期：2026-07-13
> 评估对象：`magneticraft 0.1.0` 首发候选
> 目标平台：Minecraft 1.20.1 / Forge 47 / Java 17

## 1. 结论

在“当前已经注册的内容”为交付边界时，Magneticraft 迁移到 Forge
1.20.1 且保持纯 Java 的方案已经完成工程闭环，具备发布首个候选版本的
可行性。注册、数据生成、机器、网络、多方块、世界生成、电脑、客户端表现及
三项可选兼容均已在目标运行环境中工作，未发现需要引入 Kotlin、旧模型加载器
或强制前置模组的阻断项。

- **可行性结论：高。** 迁移路径与 Forge 1.20.1 生命周期、数据和网络模型兼容。
- **验收置信度：高。** 结论由 89 项 JUnit、47 项 GameTest、确定性数据生成、
  基础客户端/专服及完整可选模组运行矩阵共同支持。
- **发布判断：GO。** 功能、运行矩阵与最终制品审计均已通过；当前制品可作为
  `0.1.0` 首发候选进入分发流程。

这里的“完成”表示达成本文定义的首发范围，不表示恢复所有未注册的历史原型，
也不承诺旧版存档、内部 API 或模型动画的逐字节兼容。

## 3. 首发范围

### 范围内

- 已注册的材料、方块、物品、流体、配方、战利品、标签和语言资源；

## 5. 架构迁移结果

迁移不是对旧 Kotlin 源码的机械翻译，而是按 Forge 1.20.1 契约重建：

1. 注册层使用 `DeferredRegister`，静态内容由 Java datagen 生成；
2. 方块实体以机器宿主和职责单一的模块组合能力、存储、配方及状态；
3. 菜单使用 32 位容器数据传输关键数值，网络包执行线程和服务端权限明确；
4. 电、热、流体和物流以守恒、有限吞吐和增量拓扑为核心约束；
5. 多方块使用声明式结构、控制器权威状态和可逆形成/解除流程；
6. 油藏与程序执行均有明确上限，避免无限资源或无界 tick 工作；
7. 机器状态持久化与客户端同步分离，渲染层只消费已同步状态。

该结构保持纯 Java 17，避免把旧加载器、Kotlin 标准库或第三方模组实现泄漏到
核心域，符合当前首发所需的 KISS、YAGNI 和依赖倒置边界。

## 6. 客户端视觉分层

客户端表现采用四层职责，而不是在运行时解析历史模型格式：

1. **静态层：** 简单内容使用 vanilla/generated JSON；审计通过的稳定部件使用
   Forge OBJ，包括 computer、grinder base、hydraulic press base 和 solar base。
2. **动态层：** 方块实体渲染器处理机器工作状态、物品、流体表面、太阳跟踪、
   多方块动态提示和机器人动画，并使用服务端同步状态。
3. **交互层：** 普通机器、进阶多方块、编程及指南界面各自消费菜单/指南数据。
4. **转换边界：** 44 个 MCX、21 个 glTF 和 23 个 OBJ 已完成盘点；MCX/glTF
   只允许离线、确定性转换，不向发布运行时增加兼容模型加载器。

精确的旧版命名网格动画仍可按
[`docs/MODEL_CONVERSION.md`](../MODEL_CONVERSION.md) 的清单逐项增强，但不应重新
耦合 1.12 模型加载器或让渲染线程解析 glTF。

## 7. StrutYourStuff 决策

StrutYourStuff 解决的是两个锚点之间可碰撞、可交互的支撑杆/长构件渲染，
不是多方块验证器，也不负责机器动画、流体或 MCX/glTF 转换。当前首发没有注册
电线杆或其他长跨度构件消费者，引入它会额外扩大 Mixin、可选 Flywheel 和加载
矩阵；固定快照还缺少根许可证文本。因此首发**不把 StrutYourStuff 作为前置或
可选依赖，也不复制其实现**。仅在未来明确恢复可选择、可碰撞的长距离电线时，
再进行独立的许可证和兼容性评审。

## 8. 可选兼容结果

- **JEI 15.20.0.133：** 注册六类 Magneticraft 配方、催化剂与运行时配方；
  基础客户端即使不安装 JEI 也可加载。淘洗配方的输出数量在领域、JSON 和网络
  入口统一限制为 1 至 10，JEI 不会静默截断合法输出。
- **CraftTweaker 14.0.60：** 暴露 `mods.magneticraft.Recipes` 的公开 Java
  配方 API，使用 `IRecipeManager` 添加 JSON 配方和按名称移除配方；不依赖反射、
  Mixin 或 CraftTweaker 内部类。开发脚本已验证添加测试配方和移除石头粉碎配方。
- **TCon 3.11.2.166 + Mantle 1.11.97：** 通过数据包增加 tungsten 材料；
  不重复定义 lead 和 steel，因为该 TCon 版本已经提供这两种官方材料。

构建期使用 `modCompileOnly`，可选开发运行时使用 ModDevGradle 的重映射配置；
普通 ZenCode Java 库保持普通运行时依赖。可选依赖不进入 Magneticraft JAR，
发布 POM 也不携带这些开发运行时依赖。

## 10. 已知正常开发环境警告

以下信息已在运行矩阵中识别，不是 Magneticraft 发布阻断项：

- Forge 开发运行的 Log4j URI 解析提示；
- Forge 组件 JAR 被当作候选模组扫描时缺少 `mods.toml` 的提示；
- 离线或不可用的 Realms 服务提示；
- 原版山羊角声音提示；
- TCon 的 shader sampler 提示。

在不同可选模组集合间复用开发世界时可能出现预期的注册表重映射警告；相同全
组合对同一世界的重启没有该警告。发布支持判断应以相同模组集重启为准。

## 11. 风险评估

| 风险 | 等级 | 处理建议 |
|---|---|---|
| 部分历史机器缺少逐网格动画保真度 | 中 | 作为后续视觉任务逐项离线转换，不阻塞首发功能 |
| 声明兼容范围宽于精确测试组合 | 中 | 对范围端点增加 CI；若无法覆盖则收窄元数据范围 |
| 1.12 存档不能保证直接升级 | 中至高 | 首发明确建议新世界；另立数据迁移项目，不在加载时猜测转换 |
| 未注册历史内容可能被误认为回归 | 低 | 在发行说明中明确范围外清单和恢复路线 |
| 可选模组后续小版本 API/数据变化 | 中 | 保持编译隔离，并为三个独立组合和全组合保留冒烟测试 |
| BER 在机器密集场景的临时对象分配 | 低至中 | 首发后以性能剖析为依据减少每帧 `ItemStack`、列表和数组复制，避免无证据的发布前重构 |

## 12. 发布建议

1. 将上述已审计 JAR 发布为 **`0.1.0` 首发候选**，不要宣称为 1.12
   全内容/全视觉等价版，并在分发页提供 SHA-256。
2. 同时发布本文、来源日志和模型转换清单；发行说明明确建议创建新世界或先备份。
3. 在 CI 中固定 Java 17，至少保留编译、89 项 JUnit、确定性 `runData`、
   47 项 GameTest、POM 隔离和基础专服启动闸门。
4. 对 JEI、CraftTweaker、TCon 维持“各自单独 + 全组合”的精确版本验证；
   在验证范围端点前，不把声明范围解释为完整实证兼容。
5. 后续优先按可见度补齐历史机器的命名部件动画；只有恢复长跨度电线玩法时，
   才重新评估 StrutYourStuff。

综上，迁移在明确范围内不存在架构、依赖或许可阻断，剩余工作属于视觉保真增强、
性能优化和后续内容扩展，不应阻止 `0.1.0` 进入首发候选阶段。
